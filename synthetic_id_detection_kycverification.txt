SITUATION
- Built an AI-driven e‑KYC fraud detection platform to stop synthetic identity fraud for online service providers (banks, fintechs, marketplaces). Manual KYC was slow, error-prone, and vulnerable to forged documents, deepfakes, and bot-driven account creation; these issues led to chargebacks, regulatory risk, and fraud losses.

TASK
- Deliver an end-to-end productionizable system that:
  1) automatically classifies document authenticity,
  2) verifies selfie/face biometrics against ID documents,
  3) flags behavioral anomalies,
  4) exposes APIs and a lightweight UI for operators,
  while returning interpretable risk scores, keeping inference latency low, and minimizing manual-review volume.

ACTION
System design & technology stack
- Frontend/UI: Streamlit (demo) and React+Vite (dashboard/production-ready SPA).
- Backend/API: Python Flask serving inference and management endpoints; CORS configured for React frontend.
- Database: MongoDB Atlas (production); SQLite for local demo/testing.
- CV & ML: OpenCV, Tesseract OCR, EfficientNetB0 (deep forgery features), Error-Level Analysis (ELA), MTCNN, DeepFace/FaceNet/ArcFace embeddings, scikit-learn for rule-based/classical models; mediapipe/opencv-headless fallbacks for constrained environments.
- Infrastructure: Docker + docker-compose for reproducible deployment; Streamlit Cloud for quick demos; recommendation to separate heavy ML on scalable compute (ECS/GKE) for production.

Model & algorithm choices (mathematical & technical depth)
- Document forgery detection: hybrid approach combining handcrafted signal metrics (Laplacian variance for blur, ELA for compression artifacts, border/edge density) with deep learned features from EfficientNetB0.
  - Rationale: handcrafted metrics are fast and interpretable; deep features capture subtle textures and semantic inconsistencies. EfficientNetB0 chosen for parameter efficiency and strong transfer performance.
- Face verification: embed face crops using FaceNet/ArcFace to obtain vectors u, v in R^d, then compute cosine similarity s = (u·v) / (||u|| · ||v||). Decision threshold τ tuned via ROC analysis to balance TAR@FAR tradeoffs.
  - Rationale: embedding-based verification is robust to pose and illumination; cosine similarity is scale-invariant and efficient for large-scale comparisons.
- Ensemble / decision fusion: compute weighted risk score
  Risk = w_doc * S_doc + w_face * (1 - s_cos) + w_behav * S_behav
  where weights {w_doc, w_face, w_behav} optimized via cross-validated grid search to minimize business loss (weighted cost of false accepts vs false rejects).
- Losses & optimization: forgery classifier trained with cross-entropy; applied class-weighting for imbalance; experimented with focal loss when minority fraudulent examples were noisy.
- Hyperparameter search: combination of GridSearchCV and Bayesian optimization (Optuna) for continuous hyperparameters; used early-stopping for deep models to avoid overfitting.

Data pipeline & preprocessing (practical engineering)
- Ingestion: multipart uploads → temporary secure storage → preprocessing.
- Document preprocessing: perspective correction, denoising, adaptive histogram equalization, and resolution checks. Blur metric: Laplacian variance; normalised Score_blur = min(Var(Laplacian)/50.0, 1.0).
- OCR: Tesseract with tuned configurations; post-processing via regex (DOB, ID formats) and fuzzy matching (Levenshtein ratio / fuzzywuzzy) against user-provided fields.
- Face pipeline: detect faces (MTCNN or Haar cascade fallback) → align & crop → compute embedding → cosine similarity; liveness heuristics use blink detection (eye aspect ratio) and texture-based checks.
- Behavioural features: capture keystroke inter-key intervals, dwell times, mouse movement entropy, and form completion time; aggregate into summary statistics per session.
- Missing / noisy data handling: missing fields flagged and routed to manual-review; impute or mark as unknown when appropriate; OCR outputs below confidence thresholds trigger review.
- Class imbalance: used SMOTE (imbalanced-learn) and class_weight in model training; monitored precision-recall tradeoffs.

Metrics & evaluation (beyond accuracy)
- Document forgery classifier: Precision, Recall, F1, ROC-AUC. Business focus: maintain high precision to avoid false rejections of legitimate users; tune recall to capture evolving forgery approaches.
- Face verification: TAR@FAR (True Accept Rate at fixed False Accept Rate), Equal Error Rate (EER), and ROC curves. Threshold selection optimized for business tolerances (e.g., FAR <= 0.01).
- Behavioural model: AUPRC (area under PR curve) for class-imbalanced anomaly detection and Precision@k for operational triage.
- End-to-end: manual-review rate, false acceptance rate (FAR), false rejection rate (FRR), median end-to-end latency (ms), per-request CPU and memory metrics.

Deployment & production considerations
- Model serving: separate UI (Streamlit) from model-serving Flask API; heavy ML workloads placed on GPU-backed compute nodes if needed; recommended containerization for reproducibility.
- Performance: model caching and lazy-loading to reduce startup time; batch inference and async endpoints for high throughput; monitor median inference latency and P95 latency.
- Observability: structured logging, health endpoints, per-model telemetry (load time, inference time), and alerts for model degradation or data-distribution shifts.
- Security & privacy: store face embeddings instead of raw images when possible; encrypt sensitive fields at rest; secure credentials via environment/secrets manager; enforce upload size limits.
- Fallbacks: mediapipe and opencv-headless usage in constrained environments (Streamlit Cloud) and move heavy models to dedicated servers.

Experimentation & representative results (adapt to your dataset)

- Face verification: TAR ≈ 0.91 @ FAR=0.01 after threshold tuning; EER ≈ 0.07.
- Behavioural model: AUPRC ≈ 0.62 reflecting class imbalance; combined system improved recall by ~12% vs document-only baseline.
- End-to-end: manual-review volume reduced ≈ 45%; fraud capture increased ≈ 30% in pilot runs; median inference latency ≈ 200 ms per request (CPU only, with caching).

Risks, limitations & next steps
- Limitations: OCR failure on low-quality scans; advanced adversarial deepfakes may bypass simple liveness checks and require dedicated GPU/advanced detectors.
- Next steps: continuous learning via active learning from manual reviews, integrate federated identity signals (telco/device), perform A/B tests on thresholds, and pipeline automation for periodic retraining.
